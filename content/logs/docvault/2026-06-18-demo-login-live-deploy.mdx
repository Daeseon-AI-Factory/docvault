## Problem

The portfolio demo needed to be usable without giving reviewers a password or mixing sample data
with the real product/friend instance.

The earlier demo stack solved the database isolation problem, but the login experience was still
awkward for a portfolio link: the reviewer needed credentials, and the final public deployment had
not been verified end to end.

## Change

Added a demo-only trial login flow:

- `DOCVAULT_DEMO_LOGIN_ENABLED=true` renders a separate **Try Demo** button on `/login`.
- `DOCVAULT_DEMO_LOGIN_USERNAME` controls which seeded demo user is signed in.
- The normal product instance leaves the flag unset, so no trial button is shown there.
- The button signs into the demo account without exposing the demo password.

Then deployed the isolated portfolio instance to the shared NCP box as its own Compose project:

- source: `/opt/docvault-demo-src`
- Compose project: `docvault-demo`
- separate Postgres/vault volumes from the product instance
- public URL: `https://docvault-demo.223.130.161.55.sslip.io/login`
- Caddy reverse proxy points to `docvault-demo-server-1:8080`

During deployment, the rsync exclude pattern `--exclude='server'` accidentally removed
`cmd/server` from the remote source tree. The fix was to exclude only the root-level build artifact:
`--exclude='/server'`. Both product and demo deploy scripts were patched.
