DocVault, 처음부터 천천히

폰/태블릿에서 편하게 보라고 만든 나만 보는 학습 페이지입니다. 카드를 탭하면 펼쳐집니다. 진도 체크는 이 기기에 저장돼요.

마음가짐 한 줄
코드를 한 줄씩 외울 필요 없습니다. 큰 그림 + "왜 이걸 썼나" 6개를 내 말로 설명할 수 있으면 끝. 이건 AI 도움으로 만들었지만 설계·결정·검증·배포를 내가 주도했다 — 그게 핵심입니다.

1. 한 문장 + 큰 그림

한 문장: "소규모 팀에서 직원 PC의 정보 유출 행위(복사·USB·외부 전송)를 수집·기록·조회하는 내부자 위협 모니터링 도구."

아닌 것(이것도 말할 줄 알아야 함): DRM ✕, ML 기반 UEBA ✕, 법적 증거 시스템 ✕, 완성된 프로덕션 보안 제품 ✕.

[직원 PC] [서버(클라우드)] [관리자] 에이전트(클립보드)─┐ osquery(파일/USB)──┼─PSK·HTTPS─▶ 수집→PostgreSQL 저장 │ └ DB트리거: 해시체인(변조방지) │ └ 규칙엔진: 위험점수→슬랙알림 └──────────────▶ 웹 UI + AI 비서 ◀── 관리자
  1. 직원 PC에 작은 에이전트(+선택 osquery) 설치
  2. 활동을 서버로 전송 (PSK로 인증)
  3. 서버가 DB에 저장, 트리거가 해시체인으로 변조 탐지
  4. 규칙 엔진이 위험 점수화 → 알림
  5. 관리자가 웹/AI 비서로 조회·지시 (롤백 가능)

2. 기술 스택 — 왜 / 대안 / 트레이드오프

면접 단골: "왜 X 썼어요?" → 각 카드의 트레이드오프를 말하면 됩니다.

① 언어: Go

뭐냐구글이 만든 언어. 컴파일하면 의존성 없는 단일 실행파일이 나옴.

왜배포가 파일 하나로 끝(서버+에이전트), 동시처리 강함, 빠르고 가벼움, 암호화 기본 제공.

대안Python(느리고 배포 무거움) · Node(런타임 필요) · Java(무겁고 장황).

트레이드오프단순·배포 쉬움(+) ↔ 코드가 다소 반복적(−). 소규모 팀이 한 언어로 서버+에이전트 = Go가 딱.

② DB: PostgreSQL

뭐냐가장 신뢰받는 오픈소스 관계형 DB.

왜정합성 최고, 트리거로 해시체인 자동화, JSON도 처리, 공짜.

대안MySQL(기능 약간 덜) · SQLite(가볍지만 동시쓰기 약함) · MongoDB(스키마 자유롭지만 정합성·조인 약함).

트레이드오프정합성·기능 강함(+) ↔ 운영이 SQLite보다 무거움(−). 감사·무결성이 핵심이면 Postgres가 정답.

③ 라우터: chi

뭐냐요청을 알맞은 처리로 보내는 가벼운 Go 라이브러리.

왜표준 net/http와 호환 + 미들웨어(감사·인증) 깔끔.

대안순수 net/http(수동) · gin/echo(기능 많고 무겁고 자체 방식 강요).

트레이드오프표준에 가까워 쉽고 잠금 적음(+) ↔ 화려한 기능은 직접 붙여야(−).

④ DB 접근: pgx + sqlc (ORM 안 씀)

뭐냐Postgres 드라이버 + SQL을 타입안전 Go 코드로 생성.

왜SQL 직접 통제 + 타입안전 + 파라미터라이즈드 쿼리로 SQL 인젝션 차단.

대안ORM(GORM): 편하지만 느려지고 복잡쿼리 약하고 "마법" 많음.

트레이드오프통제·성능·투명성(+) ↔ 타이핑 더 많음(−). 정확한 쿼리가 중요한 보안/감사엔 생SQL.

⑤ 인증: JWT (서버 세션 대신)

뭐냐서명된 출입증 토큰을 쿠키에 담음.

왜매 요청마다 세션 저장소 조회 불필요(확장성). 토큰에 신원·권한 포함.

대안서버사이드 세션: 즉시 무효화 쉬움, 대신 저장소 필요.

트레이드오프가볍고 확장 쉬움(+) ↔ 만료 전 강제취소 까다로움(−) → 짧은 만료+리프레시로 완화.

⑥ 화면: htmx + Go 템플릿 (React 대신)

뭐냐서버가 HTML 조각을 만들어 보내고 htmx가 그 부분만 갈아끼움. JS 빌드 없음.

왜복잡한 프론트 빌드 없이 동적 UI를 빨리, 한 언어(Go)로.

대안React/Vue(SPA): 앱 같은 UX, 대신 빌드·복잡도·인력 필요.

트레이드오프단순·빠른 개발(+) ↔ 초고인터랙티브 화면엔 한계(−). 내부 관리도구엔 가성비 최고.

⑦ 암호화: AES-256-GCM (청크)

뭐냐파일을 64KB 조각으로 나눠 각각 AES-256-GCM 암호화.

왜GCM은 "숨김 + 변조 탐지"를 같이. 청크로 큰 파일도 스트리밍, 순서바뀜/잘림 탐지.

대안(버림)AES-CTR: 빠르지만 변조 탐지 없음 → 위험 발견하고 GCM으로 교체(실제 사건).

트레이드오프무결성 포함 안전(+) ↔ 약간 더 무거움(−). 보안 제품엔 무조건 GCM.

⑧ 키 관리: 봉투 암호화

뭐냐파일키로 파일 암호화 → 파일키는 마스터키로 암호화해 DB 저장.

왜마스터키 하나만 지키면 됨. 키 회전·격리 쉬움.

대안마스터키로 모든 파일 직접 암호화: 단순하지만 교체 시 전부 재암호화, 격리 안 됨.

트레이드오프운영 유연성(+) ↔ 구조 한 겹 복잡(−). 다수 파일·키 회전 고려 시 표준 정답.

⑨ 로그 무결성: DB 트리거 해시체인

뭐냐로그가 들어오면 트리거가 "앞 줄 지문+내용" 해시를 자동 계산해 사슬로 엮음.

왜DB를 직접 만져 로그를 위조·삭제해도 사슬이 끊겨 탐지.

대안단순 추가전용 로그(위조탐지 약함) · 외부 불변저장소(강력하지만 복잡·비쌈).

트레이드오프비용 작고 탐지력 좋음(+) ↔ 동시입력 경쟁 처리 필요(−) → advisory lock으로 해결.

⑩ 수집: osquery + 자체 클립보드 에이전트

뭐냐파일/USB/프로세스는 osquery(기존 오픈소스), 클립보드는 우리가 만든 작은 에이전트.

왜바퀴 재발명 안 함 — 검증된 osquery 쓰고, 못 보는 클립보드만 직접.

대안전부 직접개발(시간·버그↑) · 상용 EDR(비쌈·과함).

트레이드오프비용·신뢰성 균형(+) ↔ 두 시스템 합쳐 보여줘야(−) → "통합 타임라인"으로 해결.

⑪ 에이전트 실행: 윈도우 예약 작업 (서비스 대신)

뭐냐로그인 시 사용자 세션에서 에이전트를 자동 실행하는 예약 작업.

왜서비스는 화면 없는 세션0이라 클립보드 못 읽음. 예약작업은 사용자 세션 → 캡처 가능(실제 바꾼 사건).

대안서비스(캡처 불가) · 수동 실행(꺼지면 끝).

트레이드오프캡처+자동시작(+) ↔ 격리·관리도구 덜함(−). 클립보드가 목적이면 예약작업이 정답.

⑫ AI: tool-use (RAG 대신)

뭐냐AI에 "조회/생성/배정" 툴을 주고, 자연어 지시를 그 툴 호출로 실행(OpenAI/Gemini).

왜데이터가 정형(DB)이라 문서검색(RAG)보다 SQL 툴이 맞음 → 실제 데이터 근거(할루시↓). 변경은 사람 확인+롤백.

대안RAG(문서Q&A엔 좋지만 정형데이터엔 부적합) · 파인튜닝(비쌈·과함).

트레이드오프정확·실시간·행동가능(+) ↔ 툴/권한 설계·인젝션 방어 필요(−) → 확인 게이트로 해결.

⑬ 배포: Docker Compose + 공유 박스 + Caddy

뭐냐서버·DB를 컨테이너로, 한 클라우드 박스에 다른 프로젝트와 공존, Caddy가 자동 HTTPS.

왜비용 절감(박스 공유) + 배포 단순 + 인증서 자동.

대안서버마다 직접 설치(재현성↓) · 쿠버네티스(강력하나 1인엔 과대) · Nginx(수동 인증서).

트레이드오프단순·저비용(+) ↔ 고가용성·대규모엔 한계(−). 솔로 운영엔 정답, 커지면 k8s 검토.

3. 용어 사전 (0개부터)

기본 구조 (서버·백엔드 등)

서버: 요청을 받아 처리하는, 24시간 켜진 컴퓨터(주방). 클라이언트: 요청하는 쪽(손님·브라우저).

백엔드: 뒤쪽 로직·서버·데이터. 프론트엔드: 사용자가 보는 화면.

컴파일: 사람 코드를 컴퓨터 실행형태로 번역 → 바이너리(실행파일, .exe).

미들웨어: 모든 요청 전후에 공통으로 끼어드는 단계(예: 로그인 검사·감사 로그).

데이터베이스

DB: 데이터 창고. 테이블: 엑셀 시트 같은 표. 행/열: 가로 한 줄(데이터) / 세로 항목.

SQL: DB에 말 거는 언어. 쿼리: 그 질문 한 번. 트랜잭션: "다 되거나 다 안 되거나"로 묶기.

트리거: 어떤 일이 생기면 자동 실행되는 DB 내부 장치. 마이그레이션: DB 구조 변경을 순서대로 기록·적용.

웹 통신

HTTP: 브라우저↔서버 대화 규칙. HTTPS: 그 암호화 버전(자물쇠).

API: 프로그램끼리의 정해진 창구. 엔드포인트: API의 구체 주소 하나(예: /api/events/clipboard).

라우팅: 들어온 요청을 알맞은 처리로 보내는 교통정리.

보안 (핵심)

암호화: 열쇠 없이 못 읽게 뒤섞기. 키: 잠그고 푸는 비밀 숫자. AES-256: 표준 대칭키 암호. GCM: 암호화+변조탐지 모드.

해시: 데이터의 고정 길이 "지문"(되돌리기 불가). 해시체인: 줄마다 앞줄 지문을 엮어 변조 탐지.

인증: 너 누구냐(로그인). 인가/권한: 이거 해도 되냐. JWT: 위조 못 하는 출입증 토큰. 2FA/TOTP: 비번+6자리 추가.

CSRF: 다른 사이트가 네 로그인 악용 → CSRF 토큰으로 차단. 레이트리밋: 횟수 제한(무차별 대입 차단).

PSK: 서버·에이전트가 미리 나눈 비밀키. fail-closed: 설정 빠지면 막아버림(안전). 코드사이닝: 실행파일 "검증된 제작자" 도장(없으면 SmartScreen 경고).

엔드포인트(직원 PC) · AI · 배포

에이전트: PC에 깔리는 작은 감시 프로그램. 예약작업: 로그인 시 자동 실행(사용자 세션→클립보드 캡처). osquery: PC를 SQL처럼 조회하는 오픈소스.

LLM: ChatGPT 같은 언어 AI. tool-use: AI가 정해진 기능(툴)을 호출. RAG: 문서 찾아 읽고 답. 할루시네이션: AI가 지어냄. 프롬프트 인젝션: 데이터에 명령 숨겨 AI 속이기.

컨테이너/Docker: 프로그램+환경을 담은 표준 상자. 리버스 프록시: 요청을 뒤의 서비스로 나눠주는 안내데스크(Caddy). CI: 올릴 때마다 자동 빌드·테스트하는 로봇. 커밋/브랜치/PR/머지: 코드 이력 관리 단위.

4. 핵심 개념 6개 (비유 + 면접 답변)

① 봉투 암호화

비유: 귀중품을 작은 금고(파일키)에 넣고, 그 열쇠를 더 큰 마스터 금고에 보관.

"파일마다 개별 키로 AES-256-GCM 암호화하고, 그 키들을 마스터 키로 봉인해 DB에 저장합니다 — 키 회전·격리에 유리합니다."
② 해시체인

비유: 장부 페이지마다 앞 페이지 지문을 적어두기 — 한 장 찢으면 티 남.

"감사 로그 무결성을 DB 트리거 기반 해시체인으로 보장하고, 동시 INSERT 경쟁은 트랜잭션 advisory lock으로 직렬화했습니다."
③ 에이전트 + PSK

비유: 출입증(PSK) 없으면 경비가 안 들여보냄. 클립보드는 직원 책상(사용자 세션)에서만 보임.

"에이전트는 PSK 헤더로 인증하고 서버는 PSK 미설정 시 fail-closed로 거부합니다. 클립보드는 세션 종속이라 사용자 세션의 예약 작업으로 실행합니다."
④ AI tool-use

비유: AI한테 "이 버튼들만 누를 수 있어" 하고 버튼(툴)을 줌. 위험한 버튼은 사람 확인 후에만.

"정형 데이터라 RAG 대신 tool-use를 택했습니다. 읽기 툴은 즉시, 변경 툴은 사용자 확인 턴을 거쳐 실행하고 모든 변경은 감사·롤백됩니다."
⑤ 인증·권한

비유: 출입증(JWT)에 직급이 적혀 있고, 관리자 문은 직급 확인 후 열림. 2FA는 문 앞 추가 잠금.

"접근 제어를 라우트와 저장소 경계 양쪽에 두고, 2FA 비밀은 마스터키로 암호화해 저장합니다."
⑥ 배포(Docker/Caddy)
