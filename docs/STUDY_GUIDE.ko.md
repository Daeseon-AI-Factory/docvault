# DocVault 학습 가이드 (비전공자용)

목표: **"하나도 모름" → "면접/포트폴리오에서 자신 있게 설명 가능".**
코드를 한 줄씩 외울 필요 없습니다. **큰 그림 + 핵심 결정 6개를 "왜?"까지 자기 말로** 설명할 수 있으면 됩니다. 1~2주 코스.

> 솔직한 전제: 코드 상당수는 AI(Claude + Codex)가 작성했습니다. 그게 흠은 아닙니다 — 요즘 흔합니다. **핵심은 "내가 설계·결정·검증·배포를 주도했고, 모든 선택을 설명할 수 있다"** 입니다. 이 가이드가 그걸 만들어 줍니다.

## 1. 한 문장 (제일 먼저 외우기)
> "소규모 팀에서 **직원 PC의 정보 유출 행위(복사·USB·외부 전송)를 수집·기록·조회**하는 내부자 위협 모니터링 도구."

**이 도구가 아닌 것** (이것도 꼭 말할 줄 알아야 함): DRM 아님, ML 기반 UEBA 아님, 법적 증거 시스템 아님, 완성된 프로덕션 보안 제품 아님. (출처: `docs/LIMITATIONS.md`)

## 2. 큰 그림 — 어떻게 돌아가나 (5단계)
```
[직원 PC]                         [서버 (클라우드)]            [관리자]
  에이전트(클립보드 감시) ─┐
  osquery(파일/USB 감시) ──┼─(PSK 인증, HTTPS)─▶ 수집 → PostgreSQL 저장
                          │                      └ DB 트리거: 해시체인(변조방지)
                          │                      └ 규칙엔진: 위험 점수화 → 알림(슬랙)
                          └──────────────────────▶ 웹 UI 조회 + AI 비서 ◀── 관리자
```
1. 직원 PC에 작은 **에이전트** 설치 (클립보드) + 선택적으로 osquery (파일/USB)
2. 활동을 **서버로 전송** (PSK라는 공유 비밀키로 인증)
3. 서버가 **PostgreSQL에 저장**, DB 트리거가 **해시체인**으로 변조 탐지
4. **규칙 엔진**이 위험 행위 점수화 → 슬랙 알림
5. 관리자가 **웹 UI**로 조회하고 **AI 비서**에게 질문/지시 (롤백 가능)

---

## 3. 기술 스택 (각각 "왜?" 한 줄 — 면접 단골)
- **Go**: 빠르고 단일 실행파일로 배포 간단, 동시성 처리 좋음.
- **PostgreSQL**: 신뢰성 + 트리거로 해시체인 구현 가능.
- **htmx + 서버사이드 템플릿**: 무거운 JS 빌드 없이 동적 UI — 작은 팀/단순 운영에 적합.
- **Docker + Caddy**: 배포 한 방 + 자동 HTTPS.
- **JWT**: 로그인 세션. **sqlc/pgx**: 타입 안전 SQL.
> 더 깊은 "왜"는 `docs/DECISIONS.md`(ADR)에 다 있음. 면접 전 꼭 읽기.

## 4. 핵심 개념 6개 (깊게 물어볼 것 — 비유 + 면접 답변)

### ① 봉투 암호화 (Envelope Encryption)
- **무엇**: 파일은 각자의 "파일 키"로 암호화(AES-256-GCM). 그 파일 키는 다시 "마스터 키"로 암호화해서 DB에 저장.
- **왜**: 마스터 키 하나만 잘 지키면 됨. 키 교체 시 작은 파일 키들만 다시 암호화(파일 전체 재암호화 불필요), 파일별 격리.
- **비유**: 귀중품을 각각 작은 금고에 넣고, 그 금고 열쇠들을 더 큰 마스터 금고에 보관.
- **면접 답**: "파일마다 개별 키로 AES-256-GCM 암호화하고, 그 키들을 마스터 키로 봉인해 DB에 저장합니다 — 키 회전과 격리에 유리합니다."

### ② 해시체인 (로그 변조 탐지)
- **무엇**: 로그 한 줄마다 "이전 줄의 해시 + 내 내용"의 해시를 같이 저장 → 블록체인처럼 사슬.
- **왜**: 누가 로그를 몰래 고치거나 지우면 사슬이 끊겨 바로 탐지됨.
- **비유**: 종이 장부 페이지마다 앞 페이지 지문을 적어두기 — 한 장 찢으면 티가 남.
- **디테일**: DB 트리거로 자동 계산. 동시에 여러 줄이 들어올 때 사슬이 갈라지는 경쟁 상태는 `advisory lock`으로 해결(실제 우리가 고친 버그 — `docs/troubleshooting.md`).
- **면접 답**: "감사 로그 무결성을 DB 트리거 기반 해시체인으로 보장하고, 동시 INSERT 경쟁은 트랜잭션 advisory lock으로 직렬화했습니다."

### ③ 에이전트 + PSK 인증
- **무엇**: 직원 PC의 작은 프로그램이 활동을 서버로 POST. **PSK(공유 비밀키)** 헤더로 인증.
- **왜**: 아무나 가짜 이벤트 못 넣게. 윈도우에선 **예약 작업(사용자 세션)**으로 돌려 클립보드를 캡처(서비스/세션0에선 캡처 불가 — 우리가 겪고 고친 문제).
- **면접 답**: "엔드포인트 에이전트는 PSK 헤더로 인증하고 서버는 PSK 미설정 시 fail-closed로 거부합니다. 클립보드는 세션 종속이라 에이전트를 사용자 세션의 예약 작업으로 실행합니다."

### ④ AI 비서 (Tool-use / function calling)
- **무엇**: 관리자가 자연어로 묻거나 시키면, LLM(OpenAI 또는 Gemini)이 정해진 **툴**(이벤트 조회, 사용자 생성, 호스트 배정 등)을 호출해 실제 DB로 답·실행.
- **왜 RAG 아니고 Tool-use**: 데이터가 정형(DB 테이블)이라 문서 검색(RAG)이 아니라 **SQL 툴**이 맞음 → 답이 실제 데이터에 근거(할루시 방지).
- **안전**: 변경 작업은 **사람의 명시 확인** 후에만 실행(프롬프트 인젝션 방어) + 모든 행동 **롤백 가능**.
- **면접 답**: "정형 데이터라 RAG 대신 tool-use를 택했습니다. 읽기 툴은 즉시, 변경 툴은 사용자 확인 턴을 거쳐 실행하고 모든 변경은 감사·롤백됩니다."

### ⑤ 인증·권한 (JWT · 역할 · CSRF · 레이트리밋 · 2FA)
- **무엇**: JWT 쿠키 로그인, 역할(admin/manager/employee), 관리자 페이지는 역할 게이트, CSRF 토큰, 로그인 무차별 대입 차단(레이트리밋), TOTP 2FA(비밀은 마스터키로 암호화 저장).
- **면접 답**: "접근 제어를 라우트와 저장소 경계 양쪽에 두고, 2FA 비밀은 평문이 아니라 마스터키로 암호화해 저장합니다."

### ⑥ 배포 (Docker · 공유 박스 · Caddy)
- **무엇**: 네이버클라우드 박스에 Docker Compose로 배포. 비용 절감을 위해 **다른 프로젝트와 같은 박스에 공존**(override compose로 격리), **Caddy**가 자동 HTTPS + 리버스 프록시. 포트폴리오용 **영어 데모 인스턴스**는 격리된 별도 스택.
- **면접 답**: "단일 클라우드 박스에 Docker로 배포하고 Caddy로 자동 TLS를 받습니다. 데모는 실데이터와 분리된 별도 스택입니다."

## 5. 1~2주 학습 코스 (하루 30분~1시간)
**1주차 — 큰 그림 + 결정 (코드 거의 안 봄)**
- Day 1: `README.md` 읽고 **데모 사이트 직접 로그인해서 클릭해보기** (제품 감 잡기)
- Day 2: `docs/ARCHITECTURE.md` + 위 "큰 그림 5단계" 외우기
- Day 3~4: 위 **핵심 개념 6개** 정독 → 각각 "왜?"를 **자기 말로 소리내어** 설명 연습
- Day 5: `docs/DECISIONS.md` (ADR — 왜 이렇게 선택했나, 면접 단골)
- Day 6: `docs/LIMITATIONS.md` (한계·아닌 것 — 정직하게 말할 줄 알아야 점수)
- Day 7: `docs/troubleshooting.md` + `content/logs/` 에서 **실제 문제 해결 스토리 2~3개** (면접 "어려웠던 점" 답변용)

**2주차 — 코드 살짝 + 한 번 고쳐보기**
- 폴더 구조 훑기: `internal/` 아래 각 폴더가 한 가지 책임 (auth/vault/audit/endpoint/agent/web ...)
- 관심 가는 파일 1~2개 읽기: `internal/vault/encryption.go`(암호화), `cmd/clipagent/agent.go`(에이전트), `internal/agent/agent.go`(AI)
- **작은 거 하나 직접 수정** (예: 화면 문구 한 줄 바꿔서 배포) → "내가 만질 수 있다"는 자신감

## 6. 면접 예상 질문 + 답변 뼈대
1. **한 줄 설명?** → 1번 문장.
2. **왜 만들었나?** → 소규모 팀은 비싼 보안솔루션 없이도 내부 유출을 잡고 싶다.
3. **제일 어려웠던 기술 문제?** → (택1) 해시체인 동시성 경쟁 / 윈도우 클립보드가 세션0에서 안 잡히던 문제 / SmartScreen·.bat 배포 마찰.
4. **보안은 어떻게?** → 암호화(봉투) + 해시체인 + 권한/2FA + 에이전트 PSK.
5. **AI는 안전한가?** → tool-use + 확인 게이트 + 롤백 + 인젝션 방어.
6. **AI가 코드를 썼는데 네 기여는?** → "아키텍처/기술 결정/적대적 검증/배포를 내가 주도. 실제로 적대적 리뷰로 데모 로그인 권한 footgun을 잡아 고쳤다."
7. **확장하면 뭘 바꿀까?** → 코드사이닝, 다중 테넌트, 고가용성, osquery 정식 검증, 진짜 UEBA.
8. **테스트/CI는?** → 우분투+윈도우 CI, 유닛 테스트, 윈도우 설치까지 CI로 end-to-end 검증.
